# Code Review: MR 61 - "feat: split get web results tool into two"

---

## Summary

This MR splits the monolithic `getWebResults` tool into two specialized tools:

| Tool | Purpose | Returns |
|------|---------|---------|
| **`findWebpages`** | Discovers relevant URLs via DuckDuckGo search | URLs only (no content) |
| **`crawlPages`** | Crawls specific URLs, extracts markdown with RAG | Full page content |

## ✅ Strengths

### Architecture & Design

1. **Separation of concerns** - Clean split between discovery (`findWebpages`) and extraction (`crawlPages`) phases enables flexible research workflows.

2. **Two-step research workflow** - Users can now see which sources were found before committing to deep crawls, improving transparency and control.

3. **Parallel crawling** - URLs are crawled in parallel using `Promise.all()` for ~3x speedup (lines 118-262 in `crawl-pages.ts`).

4. **RAG integration** - Crawled content is automatically indexed in Qdrant for intelligent retrieval, with deduplication and scoring (lines 304-328).

### Code Quality

1. **Comprehensive test coverage** - 914 total lines of tests covering:
   - Input validation (valid/invalid schemas)
   - Error handling (network, HTTP, JSON parse failures)
   - Successful execution paths
   - Edge cases (timeouts, duplicates, special characters)

2. **Input validation** - Zod schemas enforce:
   - URL format validation
   - Depth limits (0-3)
   - Required fields (`searchQuery`, `urls`)

3. **Error handling** - Graceful fallbacks throughout:
   - Network errors logged and returned in result
   - Timeout handling with `AbortController`
   - RAG failures fall back to direct crawl output

4. **Performance monitoring** - Built-in checkpoint timing system for debugging:
   ```typescript
   const checkpoint = (label: string) => {
     const now = performance.now();
     const elapsed = ((now - startTime) / 1000).toFixed(2);
     console.log(`[⏱️ CHECKPOINT] ${label} - ${elapsed}s`);
   };
   ```

### User Experience

1. **Depth control** - Configurable crawl depth (0-3) with clear documentation:
   - `depth: 0` - Fast (~10s), single page
   - `depth: 1-2` - Moderate research
   - `depth: 3` - Comprehensive analysis

2. **Limit guidance** - Clear warnings about `limit × depth` performance implications in prompt documentation.

3. **Blocked domains** - Automatically filters:
   - Social media (Facebook, Twitter, Instagram, LinkedIn, Reddit, YouTube)
   - Utility pages (/login, /signup, /register, /account)
   - Invalid protocols (javascript:, about:, mailto:)

4. **URL scoring algorithm** - Relevance ranking considers:
   - Domain authority (.gov, .edu, Wikipedia, news sources)
   - Title/query term matching (BM25-lite)
   - Freshness signals (current year, "latest", "breaking")
   - HTTPS preference
   - URL length penalty

## ⚠️ Issues & Recommendations

### 🔴 Critical

#### 1. `searchQuery` Schema/Documentation Mismatch

**Location:** `crawl-pages.ts` lines 73-77

```typescript
searchQuery: z
  .string()
  .describe(
    "Search query for RAG retrieval (e.g., 'Typhoons in Europe 2026'). REQUIRED - used to index and retrieve webpage content."
  ),
```

**Issue:** The description says "REQUIRED" but the schema doesn't have `.required()` - it's implicitly required. However, the prompt documentation (line 812) says "`searchQuery`: Optional topic for RAG".

**Impact:** Confusion for developers and the AI model about whether this field is mandatory.

**Fix:** Choose one:
```typescript
// Option A: Make it truly optional
searchQuery: z.string().optional()

// Option B: Keep required, update docs
searchQuery: z.string().describe("Search query for RAG retrieval. REQUIRED.")
```

#### 2. Type Safety Gap in Markdown Handling

**Location:** `crawl-pages.ts` lines 278-285

```typescript
const processedMarkdown =
  typeof rawMarkdown === "string"
    ? rawMarkdown
    : String(
        (rawMarkdown as CrawlResultObj).fit_markdown ||
          (rawMarkdown as CrawlResultObj).raw_markdown ||
          ""
      );
```

**Issue:** Uses type assertion (`as CrawlResultObj`) which bypasses TypeScript's type safety. The `CrawlResultObj` interface is defined but never used in the type check.

**Impact:** Potential runtime errors if the response structure changes.

**Fix:** Use a proper type guard:
```typescript
function isCrawlResultObj(obj: unknown): obj is CrawlResultObj {
  return (
    typeof obj === "object" &&
    obj !== null &&
    ("fit_markdown" in obj || "raw_markdown" in obj)
  );
}

// Then use:
const processedMarkdown =
  typeof rawMarkdown === "string"
    ? rawMarkdown
    : isCrawlResultObj(rawMarkdown)
      ? String(rawMarkdown.fit_markdown || rawMarkdown.raw_markdown || "")
      : "";
```

#### 3. Silent Qdrant Failures

**Location:** `crawl-pages.ts` lines 114-116, 241-243

```typescript
await ensureCollection().catch((err) => {
  console.error("[QDRANT] Failed to ensure collection:", err);
});

// And:
await ingestPage(url, markdown, searchQuery).catch((err) => {
  console.error(`[QDRANT] Failed to ingest ${url}:`, err);
});
```

**Issue:** Errors are logged but silently swallowed. The crawl continues but data may be lost without the caller knowing.

**Impact:** Silent data loss - RAG retrieval will fail but the tool reports success.

**Fix:** Add warnings to the result:
```typescript
const warnings: string[] = [];

await ensureCollection().catch((err) => {
  console.error("[QDRANT] Failed to ensure collection:", err);
  warnings.push("Qdrant collection not available - RAG disabled");
});

// Return warnings in result
return {
  markdown: finalMarkdown,
  urlContents,
  totalCrawled: urlContents.length,
  warnings, // NEW
};
```

#### 7. Character Limit Is Hard-Coded

**Location:** `crawl-pages.ts` lines 352-358

```typescript
const charLimit = 60_000;
if (finalMarkdown.length > charLimit) {
  console.log(
    `[CRAWLER] Result is too big: ${finalMarkdown.length} characters. Shortening to ${charLimit}`
  );
  finalMarkdown = finalMarkdown.slice(0, charLimit);
}
```

**Issue:** No documentation of why 60,000 or how it relates to token limits.

**Impact:** May truncation important content or exceed context limits.

**Fix:** Create a new `lib/ai/tools/constants.ts` file to centralize crawler-related constants:

```typescript
// lib/ai/tools/constants.ts
// Centralized constants for AI tools

/**
 * Maximum characters allowed in crawl results
 * ~60k characters ≈ 15k tokens (4 chars/token average)
 * Leaves room for system prompt + conversation history in 200k context
 */
export const MAX_RESULT_CHARS = 60_000;

/**
 * Domains blocked from crawling
 * Includes social media, search engines, and utility pages
 */
export const BLOCKED_DOMAINS = [
  "duckduckgo.com",
  "facebook.com",
  "twitter.com",
  "instagram.com",
  "youtube.com",
  "linkedin.com",
  "reddit.com",
] as const;

/**
 * URL patterns blocked from crawling (login/signup pages, etc.)
 */
export const BLOCKED_URL_PATTERNS = [
  "/login",
  "/signup",
  "/register",
  "/account",
  "about:",
  "javascript:",
  "mailto:",
] as const;

/**
 * Check if a URL is valid for crawling
 */
export function isValidCrawlUrl(url: string): boolean {
  if (!url.startsWith("http")) return false;
  const lowerUrl = url.toLowerCase();
  if (BLOCKED_DOMAINS.some(d => lowerUrl.includes(d))) return false;
  if (BLOCKED_URL_PATTERNS.some(p => lowerUrl.includes(p))) return false;
  return true;
}
```

Then use in `crawl-pages.ts`:
```typescript
import { MAX_RESULT_CHARS } from "./constants";

if (finalMarkdown.length > MAX_RESULT_CHARS) {
  console.log(
    `[CRAWLER] Result is too big: ${finalMarkdown.length} characters. Shortening to ${MAX_RESULT_CHARS}`
  );
  finalMarkdown = finalMarkdown.slice(0, MAX_RESULT_CHARS);
}
```

### 🟠 Medium Priority

#### 8. Blocked Domains List Should Be Centralized

**Location:** `find-webpages.ts` lines 450-458

```typescript
const blockedDomains = [
  "duckduckgo.com",
  "facebook.com",
  "twitter.com",
  "instagram.com",
  "youtube.com",
  "linkedin.com",
  "reddit.com",
];
```

**Issue:** Same list may exist elsewhere; difficult to maintain consistency.

**Fix:** Use the new `lib/ai/tools/constants.ts` file (see Issue 7):

```typescript
// find-webpages.ts
import { BLOCKED_DOMAINS, BLOCKED_URL_PATTERNS, isValidCrawlUrl } from "./constants";

function isValidExternalUrl(url: string, _text: string): boolean {
  return isValidCrawlUrl(url);
}

// Or if you need custom logic:
function isValidExternalUrl(url: string, _text: string): boolean {
  if (!url.startsWith("http")) return false;
  const lowerUrl = url.toLowerCase();
  if (BLOCKED_DOMAINS.some(d => lowerUrl.includes(d))) return false;
  if (BLOCKED_URL_PATTERNS.some(p => lowerUrl.includes(p))) return false;
  return true;
}
```

This approach:
- Keeps crawler-specific constants isolated in `lib/ai/tools/constants.ts`
- Does not require changes to `shared/config/index.ts` or `.env.local`
- Provides a single source of truth for both `find-webpages.ts` and `crawl-pages.ts`
- Makes it easy to add more crawler-related constants in the future

#### 9. Search Query Keyword Splitting Is Naive

**Location:** `crawl-pages.ts` line 105

```typescript
const searchAsKeywords = searchQuery.trim().split(" ");
```

**Issue:** Doesn't handle:
- Punctuation ("What's the weather?")
- Stopwords ("the", "and", "in")
- Multi-word concepts ("New York", "World War")

**Impact:** Reduced relevance scoring accuracy in deep crawls.

**Fix:** Use a simple tokenizer:
```typescript
const searchAsKeywords = searchQuery
  .toLowerCase()
  .match(/\b[\w']+\b/g) // Extract words
  ?.filter(w => w.length > 2 && !STOPWORDS.has(w)) ?? [];
```
